# 01 — Project Overview

## اسم المشروع

**TikTok Intelligence Platform**

## الفكرة بجملة واحدة

منصة يدخل إليها أي شخص، يكتب يوزر TikTok، ويحصل خلال ثوانٍ على تقرير احترافي كامل عن قوة الحساب، أدائه، جمهوره، ونقاط قوته وضعفه — وفي نفس الوقت تعمل المنصة كقناة توظيف تجذب أفضل هذه الحسابات للانضمام إلى وكالة TikTok LIVE.

## المشكلة التي نحلها

- المبدع لا يملك أداة واحدة تجمع له كل مؤشرات أداء حسابه (نمو، تفاعل، بث مباشر، فرصة الوصول لـ For You) في تقرير مفهوم وقابل للتنفيذ.
- الوكالات تبحث يدويًا عن مبدعين واعدين للانضمام، بعملية بطيئة وغير منظمة (رسائل مباشرة، Excel، لا تقييم موضوعي).
- لا توجد منصة عربية/إقليمية تجمع بين "قيمة فورية للمستخدم" و"قمع توليد عملاء محتملين (Leads) لوكالة" في نفس المنتج.

## من هو المستخدم

| الشريحة                        | ماذا يريدون                                     |
| ------------------------------ | ----------------------------------------------- |
| مبدعون (Creators)              | فهم أداء حسابهم، معرفة نقاط الضعف، توصيات نمو   |
| ستريمرز (Streamers)            | تقييم جاهزيتهم للبث المباشر ولانضمام لوكالة     |
| وكالات TikTok LIVE (نحن ضمنًا) | اكتشاف واستقطاب مبدعين مؤهلين، وإدارتهم عبر CRM |
| شركات تسويق ومؤثرون            | تقييم حسابات قبل شراكات إعلانية، تحليل منافسين  |
| أصحاب متاجر                    | فهم فرص الوصول لجمهور جديد عبر TikTok           |

## المنتجان داخل نفس المنصة

### المنتج 1 — TikTok Profile Analyzer (عام، لأي زائر)

يُدخل المستخدم يوزر TikTok فيحصل على تقرير يشمل: معلومات الحساب، الإحصائيات، بيانات البث المباشر، تحليل AI لقوة الحساب، نقاط القوة والضعف، تحليل فرصة الوصول للـ Explore/For You، تحليل الجمهور، وتحليل المنافسين. التفاصيل الكاملة في `03_FUNCTIONAL_REQUIREMENTS.md`.

### المنتج 2 — Agency CRM & Recruitment (داخلي + نموذج تقديم عام)

بعد التحليل، إذا كان الحساب مؤهلًا (Score أعلى من عتبة معينة، أو نشاط بث كافٍ)، يظهر للمستخدم عرض انضمام لوكالة TikTok LIVE مع نموذج تقديم. الطلبات تدخل مباشرة إلى لوحة تحكم CRM يديرها فريق التوظيف. التفاصيل الكاملة في `12_AGENCY_CRM.md`.

## أولوية العرض للمستخدم (قاعدة إلزامية)

**المنصة تُقدَّم للمستخدم كأداة تحليل تخدمه هو أولًا، وليست نموذج توظيف يخبّئ وراءه تحليلًا.** الترتيب النفسي والبصري إلزامي:

1. **أولًا**: تجربة التحليل الكاملة — المستخدم يشعر أن هذا تقرير احترافي بُني له، يفيده هو بفهم حسابه وتحسينه، بغض النظر عن أي شيء آخر.
2. **بعدها فقط**: إن كان الحساب مؤهلًا، يظهر عرض الانضمام للوكالة — كفرصة إضافية اختيارية، لا كهدف الصفحة.

هذا يعني عمليًا: بانر الوكالة لا يظهر أبدًا قبل اكتمال عرض التقرير، ولا يُصمَّم بنفس الوزن البصري لباقي التقرير (`16_UI_UX.md`، `12_AGENCY_CRM.md`). أي صياغة أو تصميم يجعل المستخدم يشعر أن "الهدف الحقيقي هو تجنيده" يُعتبر مخالفًا لهذه الوثيقة ويجب إصلاحه.

## القيمة التنافسية

- تجربة "نتيجة فورية" (Score خلال ثوانٍ) بدل تقرير API جاف.
- ازدواجية القيمة: أداة مجانية/مدفوعة للمبدع + قمع توليد عملاء محتملين للوكالة، بدون تعارض بين الهدفين.
- بنية Multi-Provider منذ اليوم الأول (`10_TIKTOK_DATA_ENGINE.md`) تسمح بالتوسع لمنصات أخرى دون إعادة هيكلة.
- منتج عربي أولًا (Arabic-first، راجع `16_UI_UX.md`) بجودة تصميم عالمية — ميزة تنافسية حقيقية بسوق ناطق بالعربية شبه خالٍ من منتجات بهذا المستوى.
- كل مؤشر تقديري (بلد المنشأ، تاريخ الإنشاء، فرصة For You، قوة الحساب) موسوم بوضوح كـ"تقديري" — شفافية تبني ثقة بدل الادّعاء بدقة غير موجودة.

## نموذج العمل (Business Model) بإيجاز

- اشتراكات (Freemium → Pro → Agency) لعدد التقارير/الميزات المتقدمة (مقارنة منافسين، تصدير PDF، تتبع تاريخي).
- توليد عملاء محتملين (Leads) مؤهلين مسبقًا للوكالة، بدل التوظيف العشوائي.
- التفاصيل الكاملة في `02_BUSINESS_REQUIREMENTS.md`.

## أهداف المرحلة الأولى (MVP)

1. محرك تحليل يعمل على حساب TikTok حقيقي واحد على الأقل (Provider: TikTok) وينتج تقريرًا كاملاً.
2. صفحة هبوط عربية RTL بجودة تصميم عالمية + صفحة تحليل عامة بدون تسجيل دخول إلزامي لأول تقرير.
3. نظام تسجيل دخول ولوحة تحكم للمبدع (حفظ تقاريره، تتبّع تاريخي بسيط).
4. نموذج انضمام للوكالة + لوحة CRM أساسية لفريق التوظيف.
5. لوحة إدارة (Admin) بصلاحيات أساسية.

التفاصيل الزمنية والمراحل الكاملة في `20_PROJECT_ROADMAP.md`.

## خارج النطاق حاليًا (Out of Scope for MVP)

- مزودو بيانات إضافيون (Instagram, YouTube, Kick, Twitch) — البنية تدعمهم لاحقًا فقط.
- تطبيق موبايل مستقل.
- API عام يُباع للمطورين (ممنوع صراحة — راجع `README.md`).
- نظام دفع بعملات متعددة/ضرائب دولية معقدة (يُكتفى بمزود دفع واحد في MVP).
