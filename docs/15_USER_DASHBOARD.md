# 15 — Creator Dashboard (User Dashboard)

تجربة المبدع بعد تسجيل الدخول. الهدف: تحويل زائر جرّب تقريرًا واحدًا إلى مستخدم يعود بانتظام (Retention، `02_BUSINESS_REQUIREMENTS.md`). كل الواجهة عربية RTL افتراضيًا (`16_UI_UX.md`).

## الصفحة الرئيسية للوحة التحكم

- بطاقة ملخّص للحساب/الحسابات المتابَعة: آخر Score، اتجاه التغيير (↑/↓ منذ آخر تحليل).
- زر "تحليل حساب جديد" بارز دائمًا.
- آخر 3 توصيات AI (من `ReportInsight` النوع `recommendation`).
- حالة الاشتراك الحالية + زر ترقية إن كانت الخطة Free.

## صفحة "حساباتي"

- قائمة كل `AnalyzedAccount` المرتبطة بالمستخدم (كمالك أو كمتابِع).
- لكل حساب: آخر Score، تاريخ آخر تحليل، زر "تحديث التحليل" (يخضع لسياسة Cache/حدود الخطة، `10_TIKTOK_DATA_ENGINE.md`).

## صفحة التقرير الفردي

نفس مكونات صفحة التقرير العامة (`03_FUNCTIONAL_REQUIREMENTS.md` FR-1) لكن مع إضافات حصرية للمسجّلين:

- رسم بياني للتطور التاريخي (إن توفر أكثر من Snapshot) — `11_ANALYTICS_ENGINE.md`.
- زر تصدير PDF (Pro+).
- زر إضافة منافس للمقارنة (Pro+).
- إن كان الحساب مؤهلاً للوكالة ولم يُقدَّم طلب بعد → بانر التأهل (`12_AGENCY_CRM.md`) يظهر هنا أيضًا وليس فقط في أول تحليل.

## صفحة المقارنات

جدول/رسم بياني جنبًا إلى جنب بين حساب المستخدم وحساب أو أكثر من المنافسين المحفوظين (`11_ANALYTICS_ENGINE.md`).

## صفحة الإعدادات

- بيانات الحساب الشخصي (اسم، بريد، صورة).
- إدارة الاشتراك (عرض الخطة، رابط بوابة الفوترة الخارجية).
- تفضيلات الإشعارات (بريد نعم/لا لكل نوع).
- تفضيل اللغة (عربي افتراضيًا / إنجليزي).
- طلب حذف الحساب/البيانات (`04_NON_FUNCTIONAL_REQUIREMENTS.md` — الامتثال).

## حالة طلب الوكالة (إن قدّم المستخدم طلبًا)

- بطاقة تعرض حالة طلبه الحالية (new/reviewed/contacted/joined/rejected) بصياغة عربية ودية للمستخدم النهائي (وليس بمصطلحات CRM الداخلية الحرفية).
- لا وصول للمستخدم لملاحظات فريق التوظيف الداخلية — تلك مرئية فقط داخل `12_AGENCY_CRM.md`.

## تجربة فارغة (Empty States)

كل صفحة فرعية بدون بيانات (لا حسابات محلَّلة بعد، لا مقارنات بعد) يجب أن تعرض حالة فارغة واضحة مع دعوة لإجراء (مثال: "لم تحلّل أي حساب بعد → حلّل أول حساب الآن") بدل صفحة فارغة أو خطأ.
