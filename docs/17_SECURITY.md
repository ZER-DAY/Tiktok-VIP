# 17 — Security

## مبادئ عامة

- كل وصول لقاعدة البيانات عبر Prisma حصرًا — لا استعلامات SQL خام غير محمية (منع SQL Injection بالتصميم).
- كل مدخل مستخدم (Query params, Body, Headers ذات الصلة) يمرّ عبر Zod schema قبل أي معالجة (`08_API_SPECIFICATION.md`).
- كل استجابة HTML قادمة من مصدر خارجي (لو أي جزء من TikTok Provider يُعرض نصًا خامًا) يُنظَّف (Sanitize) قبل عرضه في الواجهة (منع XSS).
- CSRF protection مفعّل افتراضيًا عبر آلية Better Auth القياسية للنماذج/الجلسات المعتمدة على Cookies.

## كلمات المرور والأسرار

- Hashing عبر argon2 (مفضّل) أو bcrypt، لا تخزين نص صريح تحت أي ظرف.
- كل الأسرار (DB connection string، مفاتيح OAuth، مفاتيح مزود الدفع، مفاتيح S3) في متغيرات بيئة (`.env`)، غير مرفوعة لـ Git (`.gitignore` إلزامي من `phase_01`).
- لا تسجيل (Log) لأي قيمة سرّية أو Token أو كلمة مرور حتى في حالات الخطأ.

## حماية بيانات المتقدمين للوكالة (حساسة بطبيعتها)

- حقول الاتصال (هاتف، Telegram، بريد) في `AgencyApplication` (`07_DATABASE_DESIGN.md`) مرئية فقط لأدوار تملك صلاحية `crm.view_contact_info` (`13_AUTH_SYSTEM.md`).
- كل عرض لهذه الحقول (وليس فقط التعديل) يُسجَّل في `AuditLog`.
- لا تصدير جماعي (Bulk export/CSV) لبيانات المتقدمين متاح إلا لصلاحية `agency_admin` فما فوق، مع تسجيل الحدث.

## Rate Limiting

| Endpoint                             | الحد المقترح                         |
| ------------------------------------ | ------------------------------------ |
| `POST /api/analyze` (زائر غير مسجل)  | 3 طلبات / ساعة / IP                  |
| `POST /api/analyze` (مسجل، خطة Free) | حسب `Plan.reportsPerDay`             |
| `POST /api/auth/login`               | 5 محاولات فاشلة / 15 دقيقة / IP+بريد |
| `POST /api/agency/applications`      | 5 طلبات / يوم / IP (منع Spam)        |

القيم أعلاه افتراضية قابلة للتعديل من `14_ADMIN_PANEL.md`، وليست ثابتة نهائيًا.

## أمان مصادر البيانات الخارجية (TikTok Provider)

- كل استدعاء خارجي عبر Worker معزول (`10_TIKTOK_DATA_ENGINE.md`)، مع Timeout صارم لمنع تعليق الموارد.
- ممنوع تمرير أي مدخل مستخدم مباشرة كجزء من رابط/أمر بدون Encoding/Validation (منع SSRF/Injection عبر اسم المستخدم المُدخَل).
- التحقق من أن `username` المُدخَل يطابق نمط أسماء مستخدمي TikTok المسموح (Regex محدد) قبل أي استدعاء خارجي.

## HTTPS والنقل

- HTTPS إلزامي في كل بيئة فوق Local (`04_NON_FUNCTIONAL_REQUIREMENTS.md`).
- HSTS مفعّل في الإنتاج.
- كل Cookie حساس: `secure`, `httpOnly`, `sameSite=lax` كحد أدنى.

## الخصوصية والامتثال

- سياسة خصوصية وشروط استخدام واضحتين (بالعربية أولًا)، منشورتين قبل أي إطلاق عام، توضحان: طبيعة البيانات التقديرية، عدم الانتماء الرسمي لـ TikTok، وسياسة الاحتفاظ بالبيانات.
- طلب حذف بيانات مستخدم يُنفَّذ عبر Soft delete فوري + حذف نهائي مجدول (`07_DATABASE_DESIGN.md`).
- عدم مشاركة بيانات المتقدمين للوكالة مع أي طرف ثالث دون موافقة صريحة موثّقة.

## استجابة للحوادث (Incident Response) — الحد الأدنى لـ MVP

- سجل مركزي للأخطاء (`18_DEPLOYMENT.md`) يسمح بتتبّع أي اختراق/تسريب محتمل بسرعة.
- خطة إبطال جماعي للجلسات (Force logout all) متاحة يدويًا لـ `platform_admin` في حال شك بتسريب.
