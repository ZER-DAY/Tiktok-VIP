## معايير الانتقال بين المراحل (Phase Gates)

لا تبدأ مرحلة جديدة قبل أن تحقق المرحلة السابقة:

1. الكود يعمل فعليًا محليًا (`docker compose up` أو التشغيل المباشر على السيرفر) بدون أخطاء.
2. لا توجد بيانات Mock/وهمية متبقية في المسارات الأساسية (البيانات إما حقيقية من DB أو من Provider فعلي، لا Hardcoded).
3. الاختبارات المطلوبة لهذه المرحلة (`19_TESTING.md`) موجودة وناجحة.
4. مراجعة يدوية سريعة من صاحب المشروع للنتيجة الفعلية (تشغيل التطبيق والنظر إليه) قبل الانتقال.

## أولوية الميزات ضمن كل مرحلة

عند ضيق الوقت، الترتيب الملزم للتضحية (ما يُؤجَّل أولاً عند الضغط):

1. لا يُؤجَّل أبدًا: دقة ومصداقية الـ Scores الأساسية (`09_AI_ANALYSIS_ENGINE.md`)، وضوح وسم "تقديري"، والعربية كلغة افتراضية (`16_UI_UX.md`).
2. يُؤجَّل أولاً إن لزم: ميزات Pro المتقدمة (مقارنات متعددة، PDF مصمم بشكل معقّد) — نسخة أبسط تكفي للـ MVP.
3. يُؤجَّل ثانيًا: تحليل المنافسين والفئة العمرية (الأضعف موثوقية أصلًا حسب `09_AI_ANALYSIS_ENGINE.md`) — يمكن إطلاقها كـ "قريبًا" في الواجهة دون كسر التجربة.
4. لا يُؤجَّل أبدًا: أمان بيانات المتقدمين للوكالة (`17_SECURITY.md`) والصلاحيات (`13_AUTH_SYSTEM.md`).

## ما بعد الإطلاق (Post-MVP، خارج نطاق هذه الوثائق التفصيلي)

- إضافة مزودي بيانات جدد (Instagram, YouTube, Kick, Twitch) — البنية جاهزة لهم منذ `10_TIKTOK_DATA_ENGINE.md`.
- تطبيق موبايل.
- تحسين خوارزميات AI بناءً على بيانات استخدام فعلية متراكمة (تحسين تدريجي للأوزان بدل إعادة كتابة).
- باقات مؤسسية مخصصة لشركات تسويق (تقارير Bulk)، دون تحويل المنتج إلى API عام للبيع (`README.md`).
