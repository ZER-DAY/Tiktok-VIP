# 21 — خطة إعادة تصميم الواجهات العربية

## الهدف

إعادة بناء واجهات المنصة كمنتج عربي أولًا، سريع وواضح واحترافي، مع الحفاظ على جميع الوظائف وواجهات API وقاعدة البيانات الحالية. الإنجليزية تبقى نسخة ثانوية، وكل مكوّن يجب أن يعمل في RTL وLTR.

## مبادئ ملزمة

1. العربية هي الأساس: صياغة طبيعية، RTL صحيح، وأرقام وتواريخ منسقة حسب اللغة.
2. لا نسخ حرفي من أي موقع. نستخلص النمط والتسلسل البصري ثم نبني هوية أصلية.
3. لا بيانات وهمية داخل مسارات الإنتاج. المعاينات التسويقية فقط يمكن أن تستخدم بيانات عرض ثابتة وموسومة.
4. لا تغيير في API أو Prisma أو منطق الأعمال إلا إذا كشف التدقيق عيبًا يمنع الواجهة، وعندها يوثّق قبل التعديل.
5. shadcn/ui + Tailwind CSS + Lucide + Framer Motion فقط، ولا تضاف مكتبة واجهات جديدة بلا حاجة موثقة.
6. كل صفحة بيانات لها Loading وEmpty وError وSuccess، وتعمل بلوحة المفاتيح وقارئ الشاشة.
7. الموبايل يبدأ من عرض 360px، ثم الجهاز اللوحي وسطح المكتب.

## مكتبة المراجع

تُستخدم للبحث واختيار الأنماط، لا للنسخ:

- shadcn/ui Blocks: مكونات مفتوحة وقابلة للتعديل ومتوافقة مع التقنية الحالية — https://ui.shadcn.com/blocks
- Mobbin: دراسة تدفقات التسجيل والبحث واللوحات من منتجات حقيقية — https://mobbin.com
- SaaSFrame: بنية صفحات SaaS والتسعير واللوحات — https://www.saasframe.io
- Land-book: تكوين صفحات الهبوط والـ Hero والتسلسل البصري — https://land-book.com
- Refero: حالات المنتجات والجداول والإعدادات — https://refero.design
- Godly: الحركة والتكوينات الحديثة، مع تجنب المؤثرات الثقيلة — https://godly.website

قبل تنفيذ كل مجموعة صفحات، يسجل المنفذ في `docs/ui-reference-log.md`: الصفحة، رابطا مرجع كحد أقصى، ما الذي استُلهم، وكيف جرى تغييره ليناسب العربية. يمنع نسخ النصوص أو العلامات أو الأصول المحمية.

## اتجاه الهوية

- المرجع البصري الملزم هو `docs/ui-concepts/README.md` ولوحات PNG المرتبطة بكل مجموعة routes.
- طابع: تحليلات تحريرية احترافية للمبدعين، وليس لوحة تقنية جافة أو قالب SaaS عام.
- خلفية فاتحة دافئة `#FAF9F6`، نص حبري `#111827`، أسطح بيضاء، وحدود وظلال هادئة.
- المرجاني `#FF4D67` للإجراء الأساسي، والبنفسجي `#6D5DFB` كلون ثانوي للبيانات، مع ألوان حالات دلالية ثابتة.
- تخطيطات غير متماثلة ومنظمة بحسب قرار المستخدم بدل شبكة بطاقات متساوية بلا تسلسل.
- خط عربي واضح ومتوازن، وعناوين قوية دون مبالغة.
- الحركة تشرح الانتقال والحالة؛ 150–250ms غالبًا، مع احترام `prefers-reduced-motion`.
- الوضع الداكن يمكن دعمه لاحقًا، لكنه لا يقود الهوية ولا يجوز أن يمنع اكتمال الواجهة الفاتحة المرجعية.

## خريطة التنفيذ

### UI-00 — التدقيق وخط الأساس

- جرد جميع الصفحات والمكونات والنصوص.
- تصوير الحالات الأساسية على سطح المكتب والموبايل.
- كشف النصوص الصلبة ومشاكل RTL والتكرار وعدم الاتساق.
- إنشاء `docs/ui-audit.md` و`docs/ui-reference-log.md` دون إعادة تصميم بعد.

### UI-01 — نظام التصميم والهيكل المشترك

- توحيد tokens للألوان والمسافات والحواف والظلال والحركة.
- بناء primitives الناقصة: Card, Input, Badge, Skeleton, Alert, Dialog, Table, Tabs, Tooltip.
- بناء AppShell وSidebar وTopbar وPageHeader وEmptyState وErrorState.
- توثيق أمثلة RTL/LTR وحالات focus/disabled/error.

### UI-02 — التسويق والمصادقة

- Landing، Navbar، Hero، كيف يعمل، المزايا، الثقة، الأسعار، الوكالة، Footer.
- Login، Register، Forgot password، Privacy، Terms.
- CTA واحد أساسي للتحليل، وصياغة عربية مختصرة وواضحة.

### UI-03 — رحلة التحليل والتقرير

- إدخال اسم المستخدم والتحقق منه.
- شاشة تقدم التحليل مع حالة الطابور والفشل وإعادة المحاولة.
- تقرير واضح يبدأ بالملخص ثم الأدلة والتوصيات.
- تمييز كل مؤشر تقديري بصريًا ونصيًا.
- تحسين الطباعة وتصدير PDF.

### UI-04 — لوحة المبدع

- Dashboard، Accounts، Account details، Compare، Settings.
- رسوم سهلة القراءة، جداول متجاوبة، وحالات فارغة تقود إلى إجراء مفيد.
- تنقل موبايل مناسب وعدم الاعتماد على hover.

### UI-05 — CRM الوكالة

- قائمة المتقدمين والفلاتر والبحث.
- ملف المتقدم، الملاحظات، المسؤول، وسجل تغير الحالة.
- حماية البيانات الشخصية بصريًا ووظيفيًا وعدم كشفها في الواجهة العامة.

### UI-06 — الإدارة والتدقيق النهائي

- Stats، Users، Plans، Settings، Audit logs.
- توحيد الجداول والنماذج والتأكيد قبل الإجراءات الحساسة.
- مراجعة شاملة للعربية وRTL والموبايل والوصول والأداء.

## معايير النجاح النهائية

- `/` عربي وRTL من أول رسم، و`/en` يعمل LTR دون تشوه.
- لا نص ظاهر hardcoded داخل مكونات الصفحات.
- لا تمريرات أفقية غير مقصودة عند 360px.
- تنقل كامل بلوحة المفاتيح وfocus واضح وتباين WCAG AA.
- جميع حالات البيانات الأربع موجودة.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, و`pnpm build` ناجحة.
- فحص يدوي للصفحات الأساسية على 360px و768px و1440px.
- عدم حدوث أي تغيير غير مقصود في العقود الخلفية أو الصلاحيات.
