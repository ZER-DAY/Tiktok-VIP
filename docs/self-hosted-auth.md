# الحسابات على سيرفر الشركة

للاحتفاظ برابط Vercel العام مع تخزين الحسابات محليًا، استخدم
[الربط المشفّر عبر Redis](vercel-relay.md). هذا الدليل يشرح تشغيل الموقع مباشرة على السيرفر.

تسجيل الدخول يستخدم Better Auth وجداول PostgreSQL الخاصة بالتطبيق. يمكن تشغيله
بالكامل على سيرفر الشركة دون Neon. يجب أن يتصل الموقع والـworker بنفس قاعدة البيانات
وRedis حتى تعمل الحسابات والاشتراكات والتقارير معًا.

## إعداد التشغيل

1. انسخ `.env.production.example` إلى `.env.production` على السيرفر.
2. ضع كلمة مرور PostgreSQL قوية في `POSTGRES_PASSWORD` وفي `DATABASE_URL`.
   داخل Docker استخدم اسم الخدمة `db` لقاعدة البيانات و`redis` للطابور.
   تغيير متغير كلمة المرور لا يغيّر كلمة مرور قاعدة موجودة؛ حافظ على بيانات الاتصال
   الحالية عند إعادة استخدام وحدة تخزين قديمة.
   اضبط أيضًا `REDIS_PASSWORD` ونفس الكلمة في `REDIS_URL`. الطابور يستخدم كلمة مرور
   وحفظًا دائمًا، ولا يحذف مهامًا تلقائيًا عند امتلاء الذاكرة.
3. ضع سرًا عشوائيًا في `BETTER_AUTH_SECRET`، واضبط `BETTER_AUTH_URL` و
   `NEXT_PUBLIC_APP_URL` على نفس عنوان الموقع النهائي.
4. شغّل الموقع خلف reverse proxy يوفر HTTPS على العنوان العام للسيرفر.
   المنافذ `5432` و`6379` مربوطة بـlocalhost ولا تحتاج فتحها للإنترنت.
5. بعد أخذ نسخة احتياطية من أي قاعدة موجودة، شغّل:

   ```bash
   docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build db redis web
   # انتظر اكتمال migrations وفحص صحة web قبل تشغيل worker.
   curl --fail http://localhost:3000/api/health
   docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build worker
   ```

الموقع يشغّل migrations عند بدء الحاوية. يجب تجهيز الخطط والأدوار والمزوّد في قاعدة
جديدة قبل إتاحة التسجيل. لا تستخدم seed التجريبي للإنتاج لأنه ينشئ حسابًا بكلمة مرور
معروفة وبيانات تجريبية.

## نقل الحسابات والعنوان العام

تغيير رابط الاتصال وحده لا ينقل الحسابات. انقل نسخة من قاعدة البيانات القديمة إلى
السيرفر، أو استخدم نسخة احتياطية موثوقة، ثم تحقق من الحسابات والخطط قبل التحويل.
إذا كانت Neon ترفض الاتصال بسبب الحصة، فلن يمكن تصدير الحسابات منها حتى يُستعاد الوصول.
لا تستبدل قاعدة موجودة أو تحذف وحدات التخزين أثناء التجهيز.

رابط `vercel.app` الحالي يظل يشغّل نسخة Vercel حتى تُعدّل طريقة توجيه الطلبات.
لتشغيل الموقع بالكامل على سيرفر الشركة، استخدم عنوان السيرفر الجديد في المتصفح.
العنوان الداخلي مثل `192.168.x.x` متاح داخل الشبكة فقط؛ الوصول من خارجها يحتاج عنوانًا
عامًا وتحويل منافذ الراوتر إلى الجهاز، أو اتصالًا آمنًا مخصصًا للسيرفر.

لا يلزم شراء دومين: [Let's Encrypt يدعم شهادات IP قصيرة المدة](https://letsencrypt.org/2026/03/11/shorter-certs-certbot).
إصدار الشهادة يحتاج وصولًا خارجيًا إلى منفذ التحقق وتجديدًا آليًا. لا تحوّل منافذ قاعدة
البيانات أو Redis، ولا تعرض تسجيل الدخول عبر HTTP العام. استخدم HTTP الداخلي لفحص
التشغيل فقط إلى أن تكتمل تهيئة HTTPS. ثبّت عنوان الجهاز الداخلي بحجز DHCP في الراوتر
حتى لا تتوقف قواعد التحويل عند تغيّره. ظهور IP في خدمة فحص العنوان لا يثبت وحده إمكان
الوصول الوارد؛ قارنه بعنوان WAN في الراوتر للتأكد من عدم وجود NAT إضافي لدى المزود.

قبل التحويل، تحقق من إنشاء حساب اختباري وتسجيل دخوله وخروجه، وصحة قاعدة البيانات وRedis،
ووصول مهمة تحليل إلى worker. أوقف العامل القديم بعد التحويل كي لا يظل متصلاً بالقاعدة
الخارجية. احتفظ بالنسخة القديمة والنسخ الاحتياطية إلى أن يكتمل التحقق.
