# Phase 05 — Creator Dashboard

المرجع: `docs/15_USER_DASHBOARD.md`, `docs/13_AUTH_SYSTEM.md` (كامل)، `docs/11_ANALYTICS_ENGINE.md`، `docs/16_UI_UX.md` (القسم 6)، `docs/assets/ui-design-reference.png` (**افتح الصورة وطابق شكل الشريط الجانبي، بطاقات الإحصائيات، وصفحة تسجيل الدخول منها — مرجع بصري إلزامي**).

## الهدف

نظام مصادقة كامل + لوحة تحكم للمبدع (عربية RTL افتراضيًا) تسمح بحفظ التقارير، تتبّعها تاريخيًا، مقارنتها، وتصديرها.

## المهام

### Auth كامل

1. تسجيل بريد/كلمة مرور فعلي (Hash argon2/bcrypt)، تأكيد بريد إلكتروني، استرجاع كلمة مرور — كل رسائل البريد عربية افتراضيًا حسب `preferredLocale`.
2. Google OAuth فعلي (وليس placeholder من `phase_01`).
3. Guest flow: ربط آخر تقرير ضيف بالحساب الجديد تلقائيًا عند التسجيل مباشرة بعد تحليل بدون حساب.
4. Middleware RBAC مركزي فعلي يُطبَّق على كل Route محمي من هذه المرحلة فصاعدًا.

### Dashboard

5. `/dashboard` — ملخص: آخر Score لكل حساب، اتجاه التغيير، آخر توصيات، حالة الاشتراك.
6. `/dashboard/accounts` و`/dashboard/accounts/:id` — قائمة الحسابات + صفحة تقرير فردي بإضافات المسجّلين (رسم بياني تاريخي، زر تحديث يخضع لسياسة Cache والخطة).
7. `/dashboard/compare` — مقارنة بحساب/حسابات منافسة (جدول جنبًا إلى جنب من `docs/11_ANALYTICS_ENGINE.md`).
8. `/dashboard/settings` — بيانات شخصية، إدارة اشتراك (عرض فقط في هذه المرحلة إن لم يُفعَّل مزود دفع بعد)، تفضيلات إشعارات، تفضيل اللغة، طلب حذف حساب (Soft delete فعلي).
9. تصدير PDF فعلي (Job غير متزامن، تخزين S3-compatible، رابط تحميل موقّع محدود الصلاحية) — **بالعربية RTL بشكل صحيح**، يتضمن كل أوسمة "تقديري".
10. حالات فارغة (Empty states) فعلية لكل صفحة فرعية بدون بيانات.

## معيار القبول (Phase Gate)

- تسجيل مستخدم جديد، دخول، تحليل حساب، رؤيته محفوظًا في `/dashboard/accounts` — مسار كامل يعمل فعليًا، بواجهة عربية RTL.
- تصدير PDF فعلي يُنتج ملفًا قابلاً للفتح يطابق محتوى صفحة التقرير، بنص عربي غير مشوّه.
- مستخدم بدون صلاحية معينة يُمنع فعليًا من API (403 حقيقي)، لا إخفاء واجهة فقط.

قدّم عند الانتهاء: وصف مسار اختبار يدوي كامل من التسجيل حتى رؤية تقرير محفوظ.
