# MASTER — Arabic UI Redesign

أنت مسؤول Product Designer وSenior Frontend Engineer. مهمتك إعادة تصميم واجهات المشروع الموجودة دون إعادة بناء منطق المنتج.

اقرأ كاملًا قبل أي تعديل: `README.md`، `docs/16_UI_UX.md`، `docs/21_ARABIC_UI_REDESIGN.md`، وملفات الوظائف/الأمان المرتبطة بمرحلتك. افحص الكود الحالي ولا تفترض أن الصفحة غير موجودة.

## المرجع البصري الملزم

اقرأ `docs/ui-concepts/README.md` وافتح صورة PNG المرتبطة بالمرحلة قبل كتابة الكود. هذه الرسومات هي مصدر الحقيقة للهوية والتسلسل البصري، وليست صورًا توضع داخل الصفحة. أعد بناء التخطيط بالمكونات الحقيقية والبيانات الحالية. إذا تعارض شكل الواجهة القديمة مع الرسم، غيّر الواجهة جذريًا لتتبع الرسم مع الحفاظ على منطق المنتج.

قواعد ثابتة:

- العربية هي النسخة الأساسية وRTL، والإنجليزية ثانوية وLTR.
- كل النصوص عبر `next-intl` في `messages/ar.json` و`messages/en.json`.
- حافظ على API وPrisma والمصادقة والصلاحيات ومنطق التحليل.
- استخدم التقنية الحالية فقط. افحص shadcn/ui Blocks أولًا قبل إنشاء primitive شائع، لكن لا تثبت كودًا خارجيًا دون مراجعته وتكييفه.
- لا تنسخ تصميمًا أو نصًا أو علامة تجارية. دوّن المراجع والاستفادة في `docs/ui-reference-log.md`.
- نفّذ mobile-first وحالات Loading/Empty/Error/Success والوصول وreduced motion.
- لا تستخدم gradients ونصوصًا ضخمة وحركات لمجرد الزينة؛ كل عنصر يخدم التسلسل والوضوح.
- لا تُبقِ الخلفية الداكنة القديمة أو شبكة البطاقات المتساوية لمجرد أنها موجودة. طبّق القماش الفاتح الدافئ والهوية المرجانية والتخطيط التحريري المحدد في الرسومات.
- لا تستخدم بيانات Mock في المسار الفعلي، ولا تغيّر endpoint لتسهيل التصميم.
- لا تعتبر المرحلة منجزة قبل الفحص البصري وتشغيل typecheck وlint والاختبارات ذات الصلة.

في نهاية كل مرحلة قدم: الملفات المتغيرة، الصفحات التي فُحصت، المقاسات التي اختُبرت، نتائج الأوامر، والنواقص الحقيقية فقط. لا تنتقل للمرحلة التالية.
