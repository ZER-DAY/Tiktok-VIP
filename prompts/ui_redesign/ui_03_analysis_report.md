# UI-03 — رحلة التحليل والتقرير

أعد تصميم الرحلة من إدخال username حتى التقرير النهائي.

المرجع البصري المباشر: `docs/ui-concepts/02-analysis-report-ar-rtl.png`. افصل بوضوح بين بلد إنشاء الحساب من `region_code` وبلد المحتوى المتوقع، ولا تعرض قيمة غير متوفرة كحقيقة.

- اجعل validation ورسائل الخطأ عربية واضحة، مع حالات queued/processing/failed/ready وإعادة المحاولة الآمنة.
- استخدم progressive disclosure: ملخص قوي أولًا، ثم الإحصاءات، الدرجات، الأدلة، الجمهور، المنافسون والتوصيات.
- كل قيمة تقديرية تحمل badge وشرحًا قريبًا منها؛ لا تضع disclaimer بعيدًا فقط.
- صمم score visualization قابلة للفهم دون الاعتماد على اللون وحده.
- وفر skeleton يحاكي التخطيط النهائي، error state، not-found، وحالة بيانات ناقصة.
- حسّن وضع الطباعة وPDF ولا تكسر endpoint الحالي.
- تحقق ببيانات حقيقية من API، ولا تضف mock دائمًا.

افحص analyze وreport في ar/en وعلى 360/768/1440، ثم شغّل بوابة الجودة.
